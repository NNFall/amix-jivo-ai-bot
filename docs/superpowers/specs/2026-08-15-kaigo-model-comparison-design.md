# Сравнение Gemini и Kaigo Codex Text API

## Цель

Проверить, отвечает ли production Gemini сейчас, и сравнить качество пользовательских ответов `gemini-3.1-flash-lite`, `gpt-5.6-luna` и `gpt-5.6-sol`, не переключая Jivo на новый провайдер.

## Границы

- Production-конфигурация и Jivo не изменяются.
- Kaigo-токен передаётся только временному процессу на VPS и не сохраняется на диске.
- В запросах используются только синтетические товары, имена, телефоны и ИНН.
- Kaigo оценивается как text-only модель. Отсутствие native tool calls фиксируется отдельно и не маскируется текстовым JSON-протоколом.

## Методика

1. Проверить systemd-сервисы, внутренний и внешний healthcheck, текущий вызов Gemini через production-клиент и недавние provider-ошибки.
2. Для каждого провайдера отправить четыре одинаковые ситуации, в которых все необходимые товарные факты уже явно переданы в тексте.
3. Использовать фактический системный промпт AMIX. Для Kaigo передать хронологию диалога текстом в `prompt`; для Gemini передать ту же историю сообщениями.
4. Для Luna и Sol использовать `reasoning_effort=low`.
5. Сохранить буквальные ответы, HTTP/error status, latency, usage и автоматические проверки обязательных/запрещённых фрагментов.
6. Выполнить ручную оценку корректности, естественности и пригодности для AMIX.

## Ситуации

- Короткий вопрос об адресе компании.
- Уточнение второго товара после двух найденных позиций.
- Финальная сверка заказа с исправлением количества и полным набором контактов.
- Технический вопрос без характеристик, где нельзя выдумывать ответ и нужно предложить менеджера.

## Критерий результата

Отчёт должен отдельно показывать текущую работоспособность Gemini, качество каждой модели и архитектурное ограничение Kaigo. По результатам нельзя автоматически переключать production.
