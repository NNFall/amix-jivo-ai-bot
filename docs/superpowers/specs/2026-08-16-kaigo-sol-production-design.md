# Production-переход AMIX на Kaigo Sol

## Цель

Использовать `gpt-5.6-sol` с `reasoning_effort=low` как основной production LLM, не теряя существующие действия `search_products` и `handoff_to_manager` и не добавляя сценарный backend-классификатор.

## Рассмотренные подходы

1. Один JSON-конверт от Sol — выбран. Модель за один запрос возвращает обычный ответ или один вызов функции. Backend только валидирует и преобразует результат в существующий `ToolCall`.
2. Отдельный запрос для выбора действия и второй для ответа — надёжнее структурно, но удваивает задержку, расход запросов и риск упора в лимит.
3. Определение намерения backend-правилами — быстрее, но снова превращает систему в скриптового бота и плохо работает с живой речью клиентов.

## Поток данных

1. Backend собирает полный `SYSTEM_PROMPT` и всю хронологическую историю `user` / `assistant` / `tool`.
2. История сериализуется в один `prompt`, поскольку Kaigo endpoint не принимает массив сообщений.
3. В конец `system_prompt` добавляется описание двух переданных функций и строгий формат ответа:
   - `{"type":"assistant","text":"..."}`;
   - `{"type":"tool_call","name":"search_products|handoff_to_manager","arguments":{...}}`.
4. Backend разбирает JSON, разрешает только переданные функции и возвращает результат через текущий `LLMTurnResult`.
5. Существующий `AssistantService` сохраняет вызов, выполняет функцию, добавляет результат в историю и запускает следующий раунд модели.

## Надёжность

- Ключ хранится только в server `.env`.
- HTTP 429/5xx и временные ошибки повторяются ограниченно в пределах общего таймаута.
- Невалидный JSON получает один корректирующий повтор с тем же контекстом.
- Неизвестная функция, пустой ответ или повторно невалидный формат возвращают контролируемую ошибку; произвольное действие не выполняется.
- Production Gemini-настройки остаются в `.env` для отката сменой `LLM_PROVIDER`.

## Проверка

- Unit-тесты payload, сериализации истории, парсинга обоих действий, неизвестной функции, повторного формата и usage.
- Полный существующий pytest.
- Реальный VPS-прогон сценариев из последних Jivo-диалогов: адрес, поиск по коду, несколько сообщений подряд, уточнение количества, ненайденный товар, заказ до подтверждения и handoff после подтверждения, технический подбор.
- После деплоя: services active, публичный health `200`, отсутствие ошибок в journal и подтверждённые записи `llm_calls` с provider/model Sol.

## Ограничение

Это адаптер текстового протокола, а не native function calling. Поэтому протокол и parser являются частью production-контура и должны оставаться закрыты тестами.
