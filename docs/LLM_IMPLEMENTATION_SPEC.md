# LLM + Product Search Spec (Based on External Review)

Источник: пользовательский разбор целевой архитектуры для AMIX бота.  
Этот документ зафиксирован как рабочая спецификация для дальнейшей доработки.

## 1. Ключевой принцип

- Backend отвечает за точный поиск по базе.
- LLM не решает, что является точным совпадением: это всегда делает backend.
- LLM отвечает за язык, контекст диалога и решение о handoff.

## 2. Поток обработки

1. Клиент пишет сообщение.
2. Backend принимает событие, сохраняет историю.
3. Backend до LLM пытается извлечь кандидаты артикул/код.
4. Если кандидаты есть, backend сразу делает поиск в БД.
5. LLM получает: историю, сообщение клиента, результат поиска, tools.
6. Если prelookup не был сделан и LLM понимает, что нужен поиск — вызывает `search_products`.
7. Backend выполняет tool и возвращает структурированный результат.
8. LLM формирует финальный ответ.
9. Если нужен человек — `handoff_to_manager`, backend отправляет `INVITE_AGENT`.

## 3. Правила поиска

- Поиск обязательно и по `code`, и по `article`.
- Артикул может быть неуникальным: при точном совпадении возвращаются все позиции.
- Если `exact_matches` не пустой, похожие не должны подменять точные.
- Товар из `exact_matches` не должен повторяться в `similar_matches`.

### Статусы

- `exact_found`
- `multiple_exact`
- `similar_found`
- `not_found`
- `invalid_query`
- `error`

## 4. Минимальные tools

1. `search_products`
2. `handoff_to_manager`

Без множества мелких функций (`get_price`, `get_stock`) — всё через `search_products`.

## 5. Промптовая модель

- Один основной системный промпт менеджера первой линии.
- Отдельный промпт для финального ответа по результату поиска.
- Контекст компании (контакты, график, доставка, возврат, ассортимент) разрешён только для общих вопросов.
- Товарные факты только из БД/результата функции.
